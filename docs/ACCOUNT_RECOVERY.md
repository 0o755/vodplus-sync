# 管理员密码与完整重置

重新部署只更新程序和数据库结构，不清空 D1。只要数据库已有管理员，访问时就是登录页；没有内置的默认 admin 账号或默认密码。

## 已能登录

点击侧栏底部“账号与数据”，或右上角管理员头像。

- 修改密码：输入当前密码及两次新密码。新密码最低 5 位，成功后所有后台会话失效，需要重新登录。不会改变用户、设备、文件和分享数据。
- 完整重置：点击“清空全部数据并重置”，输入当前管理员密码及大写 `RESET`。确认后清空当前 D1 中的全部业务数据，并进入管理员初始化页。

重置包含管理员、用户、设备授权、分享接口和凭证、文件字节与历史版本、记录同步、冲突、回执、日志和自定义同步规则。规则恢复默认值。表结构和迁移记录保留，不需要重新建库。

重置使用单条 SQL 触发同一事务，数据库出错会整体回滚，不留下半清空状态。此操作不能从后台撤销，操作前可先在 Cloudflare 备份数据库。同一 D1 上的其他 Worker 实例也会看到数据被清空。

## 忘记密码、不能登录

不会提供匿名访问即可清空数据的接口。请使用自己的 Cloudflare 账户：

1. 在 Worker 的绑定中确认实际使用的 D1 数据库，打开该库的控制台。
2. 如果只是忘记用户名，可先执行只读查询：

```sql
SELECT username FROM administrators;
```

3. 如果确定要清空全部数据，先部署包含 `0008_factory_reset.sql` 的版本并完成迁移。可通过下面的只读查询确认恢复功能已存在：

```sql
SELECT name FROM sqlite_master WHERE type='trigger' AND name='factory_reset';
```

4. 确认备份与清空范围后，在该 D1 控制台执行：

```sql
INSERT INTO maintenance_actions(action) VALUES('factory_reset');
```

5. 刷新后台页面，重新创建管理员。不要手工删除整个数据库，也不要删除迁移表。

这只清空云端，不自动删除 App 本地文件和历史。原设备凭证会失效，需要通过 App 的明确重置绑定流程连接新身份；不能把旧人物的未上传队列自动改归新人物。

## HTTP 500 排查

`GET /api/health` 不需要管理员登录，只返回公开表结构的就绪情况，不返回账号、设备或凭证。`missingMigrations` 用来提示可检测到的缺失结构，不能替代 Cloudflare 中的完整迁移记录与日志。

应用内部异常现在返回 `detail.code` 与 `detail.requestId`，日志只记录请求编号、操作类别和诊断码，不记录完整 URL、SQL、令牌或设备码。结构缺失、额度问题和未知异常分别处理，不能看到 500 就认定是迁移缺失。

如果连 `/api/status` 都返回 Cloudflare 自带的 HTML 404，而不是本项目 JSON，先核对当前服务器地址和 Worker 域名；这不能证明 D1 出错。
